# CapCut Draft Playbook

- **Location:** On Windows, drafts live at `%LOCALAPPDATA%\CapCut\User Data\Projects\com.lveditor.draft`. On Linux, pass a custom `draftsDir` to prepare portable drafts. **A draft has two `draft_content.json` files** (`<draft>/draft_content.json` and `<draft>/Timelines/<id>/draft_content.json`); CutRig writes both — hand-editing only one leaves CapCut showing stale content.
- **Speed & Token Rule (CRITICAL):** NEVER read raw `draft_content.json`, `draft_meta_info.json`, or `Cache/effect/*` files directly, and NEVER write Python/shell patching scripts. Always use `cutrig_capcut_inspect_draft`, `cutrig_capcut_color_grade`, `cutrig_capcut_adjust_timing`, and `cutrig_capcut_list_effects` directly in 1 call.
- **CapCut Must Be Closed Before Writing:** CapCut keeps the open timeline in RAM and overwrites disk on save, silently discarding external edits. `cutrig_capcut_adjust_timing` / `color_grade` close `CapCut.exe` first and relaunch it afterwards by default (`autoCloseCapCut`, `autoReopenCapCut`). Never advise the user to close CapCut manually — the tool already does it.
- **Version Safety (avoids "Can't open this project yet. This project requires the latest app version"):**
  - The launcher picks the **highest** installed `%LOCALAPPDATA%\CapCut\Apps\<ver>\CapCut.exe` (semver sort, not directory order). Picking the first folder launches CapCut 8.5, which cannot open a `new_version 187/189` draft and produces exactly that dialog.
  - Every write pins **both** `platform.app_version` and `last_modified_platform.app_version` to the **installed CapCut build** (highest `Apps/<ver>` folder; sibling drafts only as fallback when no install is detectable), keeping all three parts (`9.6.0`, never `9.6`), and clears `draft_meta_info.draft_new_version`. `new_version` is left untouched — CapCut 9.6 legitimately writes `189.0.0`, so the app_version fields are the only ones that must agree with it.
  - Never let the two app_version fields disagree (e.g. `platform 9.5.0` + `last_modified 9.6.0`, or `9.6` vs `9.6.0`). That inconsistent pair is what re-triggers the dialog, and CapCut silently reverts your timeline edits when it happens. `cutrig_capcut_validate_draft` reports it as an **error**.
- **Text Fit (avoids horizontal clipping past the canvas):** never leave `clip.scale` above `0.8` on wide quote blocks. `cutrig_capcut_adjust_timing` takes `textAutoFit: true` (pyCapCut bounding-box approach: scale derived from each block's own longest line, clamped 0.4–0.8, `textMaxWidthRatio` default `0.9`) or the manual `textSafeScale: 0.75`. Pair with `textYTransform: 0.15` and `textFontSize: 5.6` to restyle **every** existing text segment in one call. `textFontSize` writes both `material.font_size` and `content.styles[].size` because CapCut's renderer only honours the latter.
- **Text vs Transition Truth:** the text track composites **above** the video track, so a quote that *spans* a transition renders fine — only a quote whose **start** lands inside a transition window pops in mid-blend. `avoidTransitionsForTexts: true` therefore shifts the start past `transitionEnd + textMinGapAfterTransitionSec` and never trims duration. Do NOT cut a 6s quote down to 2s to dodge a transition; that destroys readability for no visual gain. The call returns `textOverlapCount` / `textOverlaps` (cli-anything-capcut gap-detect equivalent) — `0` means every text start is clean.
- **Health Check (run before and after a mutation):** `cutrig_capcut_validate_draft` is read-only and needs no CapCut launch. It reports `ok`/`errorCount`/`issues` for: dangling `material_id` / `extra_material_refs`, app_version pair mismatch, draft `new_version` needing a newer CapCut build, `clip.scale > 0.8`, text **start** inside a transition, and empty tracks. Treat any `severity: "error"` as a blocker — fix it before opening CapCut.
- **Undo:** every mutation writes a `<file>.<timestamp>.bak` snapshot. `cutrig_capcut_restore_backup` restores the newest content+meta pair (or an explicit `backupPath`), snapshots the current broken state first, and re-syncs `Timelines/<id>/draft_content.json`. Use it after a bad batch instead of hand-editing JSON back.
- **SRT import:** `cutrig_capcut_add_text` takes `srtPath` and imports every cue as a text segment (merged with `items`), so a generated `.srt` lands on the CapCut text track in one call — no per-line loops.
- **Audio fades:** `cutrig_capcut_insert_clips` accepts `fadeInSec` / `fadeOutSec` on audio clips. CapCut reads fades from a companion `materials.audio_fades` entry (`fade_type: 0`, microseconds) referenced by the segment's `extra_material_refs` — writing them on the segment alone does nothing.
- **Workflow:**
  1. `cutrig_capcut_inspect_draft` (for existing drafts) or `cutrig_capcut_create_draft` (e.g. `1080x1920`, `30` fps for Reels/TikTok). Run `cutrig_capcut_validate_draft` on an inherited draft before touching it.
  2. `cutrig_detect_beats` on project MP3/WAV (or `cutrig_capcut_list_audio` to browse cached CapCut `Cache/music/*.mp3` + `.beat` timestamps) before cutting clips on-beat.
  3. `cutrig_capcut_insert_clips` in ONE batched call to place `KinetRig` opener + A-roll + BGM track aligned to beat timestamps.
  4. `cutrig_capcut_color_grade` (`film`, `teal_orange`, `moody`, `warm_golden`, `clean_vivid`, or custom `adjustments`/`curves`) in 1 call for color grading.
  5. `cutrig_capcut_add_text` for timed hook titles or SRT-derived captions.
  6. `cutrig_capcut_adjust_timing` in 1 call to vary transition durations (e.g. `transitionRandomRange: { minSec: 0.4, maxSec: 1.0 }` or `transitionDurations: [0.6, 0.8, ...]`) and automatically shift text segments past transition zones (`avoidTransitionsForTexts: true`, `textMinGapAfterTransitionSec: 0.3`). NEVER refuse or ask the user to manually edit transition durations or drag text blocks in CapCut Desktop.
  7. `cutrig_capcut_validate_draft` again — `ok: true` and `textOverlapCount: 0` before telling the user it is ready.
- **Export Fallback:** CapCut Desktop has no official headless CLI export. Open the draft in CapCut and press `Ctrl+E` (or hand off to optional `AppRig` Desktop MCP if UI automation is enabled).
